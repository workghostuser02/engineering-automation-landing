# Состояние проекта

## Проект

Учебный одностраничный сайт инженерных услуг на основе реального объявления FL.ru. Это не оплачиваемый заказ и не официальный сайт автора объявления, производителя оборудования или реальной инженерной компании.

## Текущее состояние

Финальная учебная версия опубликована через GitHub Pages: https://workghostuser02.github.io/engineering-automation-landing/

## Сделано

- Создана локальная структура HTML, CSS и Vanilla JavaScript.
- Заполнены основные секции: первый экран, услуги, объекты, этапы работы, FAQ и контакты.
- Сделана честная учебная форма: нативная проверка полей работает, данные никуда не отправляются.
- Проверены внутренние ссылки и исправлено отображение блока объектов на планшетной ширине.
- Выполнена локальная проверка структуры, ссылок, нативной валидации формы, клавиатурной доступности и визуального отображения на узком, планшетном и широком экране.
- Усилена защита от горизонтального переполнения: длинные заголовки переносятся безопасно, внутренние колонки могут сжиматься, мобильная навигация компактнее.
- Проект отделён от лендинга фотографа более строгой инженерной дизайн-системой: техническая сетка, прямые формы, маркировка этапов и сдержанная контрастная палитра.
- Из публичного текста удалена привязка к конкретному производителю; используется нейтральное описание автоматики отопления.
- Добавлены локальные правила проекта и запрет публикации без отдельного указания пользователя.
- Папка проекта переименована в нейтральную `engineering-automation-landing` перед подготовкой Git-репозитория.
- Добавлены favicon, базовые Open Graph-метаданные, `.gitignore`, изображение для README и заготовка социального предпросмотра.
- README переработан для портфолио: описаны задача, структура, технологии, доступность, ограничения учебной формы и условия коммерческого использования.
- Продающая структура проверена: CTA виден на первом экране, следующий шаг сформулирован явно, форма снабжена списком исходных данных.
- Исправлена секция FAQ: сокращён лишний вертикальный разрыв, добавлены содержательные ответы, первый ответ открыт по умолчанию, а состояния аккордеона обозначены знаками «+» и «−».
- Добавлен законченный тематический фотоблок: шкаф управления, пусконаладка и инженерный контур. Изображения созданы специально для учебного проекта, оптимизированы и снабжены содержательными подписями и `alt`.
- Уплотнена секция услуг: на ширине 681–900 px используется сетка из двух карточек, третья карточка той же ширины центрируется; сокращены внутренние отступы и расстояние между номером и заголовком. На 320–390 px сохранён один читаемый столбец.
- Добавлена визуальная глубина без расширения палитры: три нейтральные градации фона, облегчённые разделители, мягкие тени карточек и состояния основного оранжевого акцента. После добавления полноширинных фонов устранено горизонтальное переполнение.
- Кнопки отполированы в сдержанном стиле: радиус 8 px, лёгкая акцентная тень, минимальный градиент основной кнопки, плавные состояния hover и active; вторичная текстовая ссылка оставлена плоской для сохранения иерархии.
- В карточки решений добавлены три оригинальные контурные SVG-иконки; график получил подпись периода «последние 8 часов»; терминология меню проверена и унифицирована вокруг названия «Решения».
- По проверке в DevTools исправлена ширина 318 px: введена отдельная сверхузкая шкала заголовков и кнопок, чтобы длинные слова не обрезались и не разбивались посередине. Диапазон 375–390 px не изменён.
- После сравнения трёх концепций выбран и установлен фирменный знак «Управляемый поток»: график параметра внутри контура. Тем же знаком обновлён локальный favicon.
- Навигация в шапке оформлена как компактная светлая панель с тонкой рамкой, мягкой тенью и акцентным hover-состоянием; на мобильных ширинах сохранена компактность и доступная область нажатия.
- Обновлены портфолио-обложка `images/preview.png` и социальный предпросмотр `images/og-preview.png` с финальными логотипом, меню, CTA и панелью системы.

## В работе

- Портфолио-версия подготовлена, проверена и зафиксирована в локальном Git-репозитории. Публикация ожидает выбора удалённого репозитория и отдельного подтверждения отправки.

## Запланировано

- Создать отдельную учебную копию формы для безопасной отправки заявок в Telegram.
- Создать бота через официальный `@BotFather` и не размещать токен в публичных файлах.
- Подключить серверный обработчик, проверку данных, защиту от спама и состояния успеха/ошибки.
- Выбрать и проверить хостинг, поддерживающий обработчик, затем выполнить тестовую отправку.
- После успешной проверки обновить портфолио честным описанием освоенной функции.

## Требует ручного действия пользователя позже

- Коротко просмотреть локальную страницу на своём телефоне при ширине около 320–390 px.
- Создание Telegram-бота в `@BotFather` по пошаговой инструкции.
- Выбор рабочего чата для получения заявок.
- Выбор хостинга и подтверждение публикации.
